## 状态

- 阶段：初版开发补全任务，待执行。

- 当前实现基线：默认环境和隔离环境共用工作区模型渠道、模型目录、Gateway 和启动方案数据模型；前端在 `src/App.tsx` 中同时渲染两张运行环境卡。

## 产品范围

### 首版必须可用

1. **模型渠道管理**：新增、编辑、删除 API Key Provider；密钥只进入系统凭据库，列表和诊断只显示脱敏信息。
2. **连通性检测**：读取 `/models`，执行最小文本检测，明确区分认证失败、无法连接、协议不兼容和上游错误。
3. **工作区模型选择**：从已检测目录选择模型，处理同名模型的公共 ID，设置默认模型并保存工作区修订。
4. **默认 App 配置**：把选定模型路由应用到默认 App 的兼容配置；保留字段级 marker，支持重启后生效、显式恢复和外部改动保护。
5. **默认 App 启动**：从 3R 启动默认 App 时补充回环代理排除变量；展示“请用 3R Codex 启动”的 502 提示。
6. **Gateway 数据面**：启动/复用本机 `codex-gateway` sidecar，健康检查、模型路由、Responses 透传和受限 Chat 转换按能力声明执行。
7. **诊断与恢复**：展示状态、时间、路由、HTTP 状态、耗时、错误层级和下一步；支持清理脱敏历史；不记录请求/响应正文或凭据。
8. **认证方式识别**：在不展示凭据原文的前提下，区分 ChatGPT 账号、API Key、未检测到和不可读取，并同时展示当前活动 Provider/路由。
9. **发布验收**：对默认 App 的首次配置、再次打开、重启 Gateway、上游 4xx/5xx、系统代理拦截回环和恢复路径完成 macOS 手动验收。

### 首版明确暂缓

- 隔离 App 的启动、实例中心、隔离 App 配置编辑和隔离 CLI 入口暂不向用户开放。
- 不删除隔离环境的数据模型、数据库字段或 Rust 命令，避免破坏后续恢复和已有本地数据。
- 不把隔离 App 自动降级成默认 App；隔离入口保持可见但为明确的“暂缓开放”禁用态。
- 不在本切片处理三方模型旧会话继续问题；该问题保留为独立诊断任务，不能用删除历史字段的方式规避。

## 隔离环境禁用设计

### 行为

- 给隔离运行环境增加明确的发布开关（建议前端常量或后端兼容快照字段），首版固定为关闭。
- 隔离卡、卡内配置入口、渠道增删、默认模型选择、实例中心、隔离 App 启动和隔离 CLI 启动全部不可操作。
- 卡片显示“隔离环境暂缓开放”及原因：“首版优先稳定默认 App；隔离 App 的签名、目录隔离和真实桌面验收完成后再开放。”
- 禁用态不触发 `onLaunchApp`、`onLaunch`、`onEdit`、`onOpenInstances` 或任何写入命令；键盘聚焦和屏幕阅读器应能读到禁用原因。
- 后端命令仍保留防御性校验：即使旧 UI 或外部调用发起隔离 App 启动，也返回结构化 `managed_app_unavailable`，不启动默认 App 代替。

### 视觉

- 隔离卡使用普通不透明 surface，移除玻璃效果（透明度、`backdrop-filter`、装饰性阴影和 hover 提升）。
- 禁用态降低对比度但保留标题、原因和边界信息；不得用仅颜色区分状态。
- 默认卡保持当前主 CTA；隔离卡不抢占主视觉层级。
- 增加浅色、深色、窄窗口和键盘导航验收，确保没有横向溢出。

## 验收标准

### 默认 App

- 新用户可以在工作区完成“添加渠道 → 检测 → 选择模型 → 应用配置 → 启动默认 App”。
- 已有默认 App 历史继续可见；恢复操作只移除仍与 3R marker 精确匹配的字段。
- Gateway 停止、上游错误、系统代理拦截和配置冲突都显示可理解的原因与下一步。
- 诊断、UI 快照和日志不出现 API Key、Authorization、Cookie、实例密钥、请求正文或响应正文。
- 3R 启动的默认 App 能访问回环 Gateway；Finder/Dock 直开时若被系统代理拦截，页面明确提示支持路径。

### 隔离环境

- 隔离卡可见但所有操作不可执行，点击、键盘和辅助技术均不会触发启动或写入。
- 隔离卡显示暂缓原因，浅色/深色下均为不透明普通卡片，无 `backdrop-filter` 或玻璃 hover 效果。
- 后端收到隔离 App 启动请求时返回 `managed_app_unavailable`，不会打开默认 App。
