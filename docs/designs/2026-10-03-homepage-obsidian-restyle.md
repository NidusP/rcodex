# 首页按 Obsidian 设计稿还原

> 状态：已实现。2026-10-03。类型检查通过。未运行 tauri 开发窗口。
>
> 日期：2026-10-03。对照 [screen.png](stitch_cyberpunk_codex_api_dashboard/screen.png)、[code.html](stitch_cyberpunk_codex_api_dashboard/code.html) 和 [DESIGN.md](stitch_cyberpunk_codex_api_dashboard/DESIGN.md)。

## 目标

首页改成设计稿的深色表面和电青色重点。默认调用模型和 API 登录渠道留下，继续写入原来的字段，只改样式。渠道行继续可以拖拽排序。工作区要暴露哪些模型，改在渠道面板里勾选，不再打开启动入口抽屉。

设计稿里的进程号、内存、延迟、多空间和调用次数是示意。没有对应的真实读数就不画。

## 从上到下

标题栏不动。系统窗口按钮、品牌、Gateway 状态、版本、主题和刷新都留在现在的位置。设计稿 header 里的窗口圆点和人物头像不进页面。

标题栏下面只有三块：

1. 空间条。左侧是隔离实例标签。每个标签对应一条 managed_app 启动方案；「新增实例」复制当前实例的渠道和模型并切过去。右侧是模型渠道入口，打开现有模型渠道抽屉，并显示真实的已加入渠道数。同时仍只能运行一个受管理 App。
2. 渠道面板。保留加入菜单、确认后才写入、拖拽排序、移除和重新检测。每一行展开后勾选该渠道已探测到的模型，勾选结果仍写入现在的工作区模型目录。行样式改成设计稿的深色表格行，去掉左侧色条。
3. 控制带。从左到右是默认调用模型、API 登录渠道，然后是一排纯图标：启动 App、实例详情、请求记录、打开隔离目录、打开默认 Codex。启动 CLI 使用终端图标，但入口隐藏。启动 App 是播放图标；未运行时提示「启动当前app实例」。2026-10-10 起，运行中直接显示停止图标，提示「停止当前app实例」，不再等悬停。打开默认 Codex 仍用应用图标。

隔离说明那一行删除，不留空位。

## 渠道面板上的模型选择

现在勾选模型是在启动入口抽屉里完成的。那个抽屉删除之后，选择改到渠道面板：

- 每个已加入渠道在原来的模型名位置直接列出可勾选的对话模型。复选框横向排列，放不下就换行，不再使用「选择模型 / 收起模型」。
- 已进入工作区的模型显示为勾选。勾选或取消后，沿用现在的工作区保存，不新开一条写入路径。
- 图像生成模型不在这里勾选，行下说明它们用于单独出图。Codex 系统角色模型仍隐藏，N 大于 0 时说明它们用于自动审核或子代理等特殊调用，不会出现在 Codex 模型目录，也不能加入工作区。
- 还没探测过，或这次没有可勾选的对话模型时，显示「尚未探测」或「这次探测没有可勾选的对话模型。」，并提供刷新模型目录。不在这里编造模型名。
- 加入确认里的「去选择模型」删除。确认加入仍只把渠道写入工作区。模型在该行上直接勾选。
- 2026-10-10：添加渠道不再确认。下拉选中后直接写入当前隔离空间，并排到第一个。仍不自动勾选模型。
- 2026-10-10：加入渠道不改已经选好的默认调用模型和 API 登录渠道。默认模型按已保存的模型顺序，不随渠道先后变化。原先只有一个渠道时，那个渠道继续作为登录渠道。
- 运行中的实例锁定时，勾选禁用，原因仍是现在的锁定说明。

默认模型选择器只列出已经勾选的模型。取消最后一个勾选时，如果它正是默认模型，按现在的保存规则处理，不在界面上另造一条规则。

## 图标操作

控制带右侧不再使用「更多」菜单。启动 App、实例详情、请求记录、打开隔离目录、打开默认 Codex 都是纯图标，Tooltip 说明动作。启动 CLI 入口隐藏。

- 启动 CLI、启动 App 仍走原来的启动。
- 实例详情。打开现有实例抽屉。
- 请求记录。打开现有诊断抽屉。
- 打开隔离目录。
- 打开默认 Codex。

导入项目会话和按清单同步设置从前端移除，不再从首页打开。对应后端命令保留，这次不删除。没有隔离实例时，实例详情、请求记录和打开隔离目录不可用。正在打开目录或默认 Codex 时，对应按钮禁用并说明原因。

## 编辑入口

首页不再保留「调整模型」和铅笔按钮「调整渠道和模型」。它们打开的启动入口抽屉删除。官方账户那条已经关闭的打开路径一并去掉，不留一个打不开的入口。

## 默认模型与登录渠道

这两个选择器继续用现在的选项、禁用条件和保存回调。

外观改成控制带里的深色格：

- 背景接近 #151821，边框 1px solid #262B3A，圆角 8px。
- 小标题用等宽字，颜色 #94A3B8。去掉 AUTO-ROUTED 和 TOKEN_BOUND。
- 选择框背景 #0F1117。聚焦时边框变为 #00E5FF。
- 下拉层用 #1C202C，选中项用青色文字和淡青底。
- 格内保留一行说明：默认模型是启动时的主模型，登录渠道是会话鉴权来源。

CLI 和 App 放在这两个格子右侧，和实例详情、请求记录、打开隔离目录、打开默认 Codex 一样只显示图标，Tooltip 说明动作。App 启动用电青色实底，CLI 用深色描边。后四项用更轻的图标按钮，避免和启动抢主操作。

- 「调整模型」、底部铅笔按钮，以及 LaunchPresetDrawer。
- 只为这个抽屉存在的首页打开状态。模型勾选状态改放到渠道行上。
- 「去选择模型」。
- channel-row-tick，以及 tone-cyan、tone-amber、tone-magenta。
- 空间条上的实例记录和诊断按钮。它们改成控制带上的纯图标。

CSS：

- surface.css 里 .channel-row-tick 和三套 .tone-*。
- .calibration-field.is-model 和 .is-login 的青、品红标题色。
- surface.css 245 行附近已经失效的两列 .console-stage。
- 底部 runtime-target-actions 里只服务铅笔按钮的样式。CLI、App 和其余图标操作的样式改到控制带。

先改 DOM，再删没有引用的 CSS。

## 非目标

- 不启用第二个隔离空间。
- 不新增进程号、内存、延迟或映射路径。
- 不改拖拽排序、加入确认、移除、重新检测、CLI 启动、App 启动，以及模型勾选的保存语义。
- 不改模型渠道抽屉、诊断抽屉、实例抽屉和添加渠道弹窗的内部结构。
- 不引入 Tailwind、Material Symbols 或在线字体。
- 本轮不启动 pnpm run tauri:dev。

## 验收

- 标题栏不变。其下顺序是空间条、渠道面板、控制带，中间没有说明段落。
- 空间条左侧是当前隔离 App 标签，右侧是模型渠道入口。
- 渠道行可以拖拽排序。展开一行可以勾选该渠道的模型，锁定时不能改。
- 控制带能改默认模型和登录渠道。启动 CLI、启动 App、实例详情、请求记录、打开隔离目录、打开默认 Codex 都是纯图标，Tooltip 说明动作。
- 首页没有「更多」菜单，也不再打开导入项目会话或按清单同步设置。后端命令保留。
- 首页没有调整或编辑按钮，也没有启动入口抽屉。

## 并行实现

文件所有权不重叠。集成由主会话在三块都落地后写入 `src/App.tsx`。

- `src/workspace-model-selection.ts`：从启动入口抽屉抽出探测模型的公共 ID 和勾选切换，不接界面。
- `src/workspace-surface.tsx`、`src/channel-sort-list.tsx`：空间条、渠道展开勾选、控制带。
- `src/surface.css`、`src/styles.css`：新首页样式，并删除色条、分色和失效布局。
- `src/App.tsx`：去掉第二标题栏和启动入口抽屉，把勾选接到现有 `create_managed_launch_preset`。
