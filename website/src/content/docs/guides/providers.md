## Provider 是什么

Provider 是一个模型服务渠道，包含名称、Base URL、协议能力和 API Key 修订。它不等同于官方 Codex 账户，也不代表上游账户余额。

## 推荐流程

1. 保存 API Key Provider。
2. 执行 `/models` 和最小文本检测。
3. 查看渠道能力：Responses 透传或受限 Chat 转换。
4. 在工作区选择模型并设置公共显示名。
5. 保存启动方案，让路由在启动时固化。

## 模型选择规则

- 未勾选的模型不会暴露给受管理入口。
- 同名模型会自动按 Provider 区分公共 ID。
- 模型目录可以手工映射，但来源必须明确。
- 不按模糊名称猜测渠道，也不因 401/502 自动换渠道或重试 POST。

## 能力边界

上游只支持 Chat Completions 时，R Codex 只提供声明过能力范围内的文本转换，不伪造工具、图片、MCP 或多轮推理兼容性。

同一句话交给不同渠道，模型的绕路方式并不一样。2026-10-13 的桌面文件测试记在[一次桌面文件测试](/rcodex/guides/field-note/)。
